# AAD Site Import — 라이노용 대지 컨텍스트 가져오기

브이월드 대지 정보(필지 경계·항공사진·대지 개요)를 **라이노 안으로** 가져온다.
설계자가 매번 손으로 만들던 컨텍스트 작업을 대체하는 것이 목적이다.

## 구조

```
Rhino 스크립트  →  AAD 서버(Next.js)  →  브이월드 / NED API
 (얇은 클라이언트)      (키 보관·정규화)
```

플러그인에는 **API 키가 들어가지 않는다**. 서버가 키를 들고 있으므로 스크립트를
사내에 배포해도 키가 새지 않는다 (CLAUDE.md 절대 규칙). 나중에 데이터 소스를
S-MAP 등으로 바꿔도 스크립트는 고치지 않아도 된다 (architecture.md C-6).

## 사용법

1. AAD 서버를 띄운다 — `npm run dev` (기본 `http://localhost:3000`)
2. 라이노에서 `_RunPythonScript` → `rhino/aad_site.py` 선택
3. 주소 입력 → 대지 선택 → 범위 프리셋 선택

서버 주소가 다르면 환경변수 `AAD_SERVER`로 지정한다.

## 프리셋 (라이노가 감당할 범위로 묶어둠)

| 프리셋 | 반경 | 항공사진 | 타일 수 | 합성 크기 |
|---|---|---|---|---|
| 대상지 | 100m | z20 (0.12m/px) | 64장 | 2048px |
| 근린 | 300m | z19 (0.24m/px) | 121장 | 2816px |
| 광역 | 500m | z18 (0.47m/px) | 100장 | 2560px |
| 필지선만 | 300m | 없음 | 0 | — |

반경과 화질을 자유 조합하게 두지 않는 이유는 실측 때문이다.

**필지·건물은 부담이 아니다** (압구정 실측):

| 반경 | 필지 | 정점 | 데이터 |
|---|---|---|---|
| 100m | 17개 | 362 | 0.02MB |
| 300m | 170개 | 1,877 | 0.11MB |
| 500m | 539개 | 5,328 | 0.34MB |

**항공사진이 병목이다.** 500m를 z20으로 깔면 타일 1,156장·8704px(원본 289MB)이 되어
라이노가 감당하지 못한다. 그래서 반경이 커지면 줌을 낮춘 조합만 제공하고,
타일 수가 200장을 넘으면 아예 중단한다.

타일 1장 왕복이 약 0.6초라 순차 다운로드는 121장에 80초가 걸린다 — 12개씩 병렬로 받는다.

## 만들어지는 것

| 레이어 | 내용 |
|---|---|
| `AAD::대상필지` | 검색한 대지의 경계 (주황) |
| `AAD::주변필지` | 반경 내 나머지 필지 (회색) |
| `AAD::항공사진` | 합성 항공사진 PictureFrame (Z=-0.05, 선 아래) |
| `AAD::대지정보` | 용도지역·면적·도로접면·기존건축물·건축사 확인 문구 |

필지 폴리라인에는 `pnu`, `jibun`이 UserText로 붙는다.

## 좌표계

대지 중심을 원점으로 하는 **로컬 미터 좌표**(등장방형 근사)를 쓴다.
웹 앱의 `src/lib/map/draw.ts`와 같은 방식이라 두 도구가 좌표를 공유한다.
`EarthAnchorPoint`도 함께 설정하므로 지리 좌표가 유지된다.

## 아직 없는 것

- **지형(DEM)** — 브이월드에 고도 REST API가 있는지 미확인. 필요하면 국토정보플랫폼
  수치표고모델을 받아 변환하는 별도 경로가 필요하다.
- **주변 건물 매스** — 건축물대장 높이 × 필지 경계 압출로 만들 수 있다(서버 API는 이미 있음).
  Extrusion 또는 Mesh로 생성해야 하며, BRep으로 수백 개를 만들면 느려진다.
- 정식 배포 형태(.rhp 플러그인, Yak 패키지) — 지금은 스크립트 파일이다.
