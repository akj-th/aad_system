# AAD Site Import — 라이노용 대지 컨텍스트 가져오기

브이월드 대지 정보(지형·항공사진·필지·주변 건물)를 **라이노 안으로** 가져온다.
설계자가 매번 손으로 만들던 컨텍스트 작업을 대체하는 것이 목적이다.

## 구조

```
Rhino 스크립트  →  AAD 서버(Next.js)  →  브이월드 REST / XDServer(3D)
 (얇은 클라이언트)      (키 보관·정규화)
```

플러그인에는 **API 키가 들어가지 않는다**. 나중에 데이터 소스를 S-MAP 등으로
바꿔도 스크립트는 고치지 않아도 된다 (architecture.md C-6).

## 설치 (한 번만)

라이노에서 `_RunPythonScript` → `rhino/install_aad.py`

`AAD` 명령어가 등록된다. 별칭은 라이노를 껐다 켜도 남는다.

## 사용법

라이노 명령행에 **`AAD`** 를 치면 끝이다.

```
AAD → 주소 입력 → 1단계 광역 범위 → 2단계 코어 반경
    → 3단계 건물 재질 → 규모 확인 → 가져오기
```

서버(`npm run dev`)를 미리 켤 필요가 없다. 꺼져 있으면 스크립트가 프로젝트
폴더에서 대신 띄우고 기다린다(실측 3초, 첫 기동은 컴파일 때문에 30초 정도).
이미 떠 있으면 아무것도 하지 않는다 — 중복 기동은 하지 않는다.
라이노를 닫아도 서버는 계속 떠 있으므로 두 번째 실행부터는 즉시 시작된다.

서버 주소가 다르면 환경변수 `AAD_SERVER`로 지정한다. 이 값이 설정돼 있으면
원격 서버로 보고 자동 기동을 하지 않는다.

명령어를 쓰지 않고 그때그때 실행하려면 `_RunPythonScript` → `rhino/aad_site.py`.

## 두 단계로 범위를 정하는 이유

광역을 통째로 고해상도로 가져오면 라이노가 감당하지 못한다.
**멀리는 성기게, 대상지 주변은 촘촘하게** 가져온다.

**1단계 — 광역 범위** (조감도용 지형·항공사진)

| 옵션 | 반경 | 지형 격자 | 항공사진 |
|---|---|---|---|
| 1km | 1,000m | 161² | z17 |
| 2.5km | 2,500m | 193² | z16 |
| **5km (기본)** | 5,000m | 257² | z14 |
| 10km | 10,000m | 289² | z13 |
| 25km | 25,000m | 337² | z11 |
| 50km | 50,000m | 385² | z10 |

**2단계 — 코어 반경** (최고 해상도 + 필지·건물)

| 옵션 | 반경 | 지형 격자 | 항공사진 |
|---|---|---|---|
| 100m | 100m | 129² | z20 (0.12m/px) |
| 300m | 300m | 193² | z19 |
| **500m (기본)** | 500m | 225² | z19 |

**3단계 — 주변 건물 재질**

| 옵션 | 결과 |
|---|---|
| **단색 매스 (기본)** | 형태는 실물 그대로, 재질은 밝은 회색 1개 |
| 실사 텍스처 | 브이월드 사진 재질 그대로 (동당 1장) |

컨텍스트를 무채색으로 두고 자기 안을 강조하는 실무 관행에 맞고, 파일도 가볍다.
단색이면 건물 재질을 객체가 아니라 **레이어에 걸어** 상속시킨다 — 객체 재질로 붙이면
라이노가 저장할 때 객체 수만큼 재질을 복제해(38동 → 재질 38개) 열 때마다 그만큼
프리뷰를 만든다. 색을 바꾸려면 `AAD::주변건물` 레이어 재질 하나만 고치면 된다.

가져오기 전에 **예상 규모(정점 수·타일 수)를 보여주고 확인**을 받는다.
타일이 240장을 넘으면 줌을 자동으로 한 단계씩 낮춘다.

광역 지형은 코어 부분을 **비워서(구멍)** 만들기 때문에 두 메시가 겹치지 않는다.

**코어 반경은 광역 격자선에 맞춰 올림된다** — 500m 요청이 광역 2.5km(격자 26.04m)에서는
520.83m, 5km(격자 39.06m)에서는 507.81m 가 된다. 격자에 맞추지 않으면 구멍이 셀
절반만큼 커져 두 지형 사이에 **빈 띠**가 생긴다(5km 약 20m, 25km 약 74m).
셀은 **전체가 구멍 안에 들어올 때만** 비운다 — 중심으로 판정하면 같은 띠가 생긴다.

## 만들어지는 것

| 레이어 | 내용 |
|---|---|
| `AAD::지형_광역` | 광역 DEM 메시 + 항공사진 텍스처 (코어 부분은 비어 있음) |
| `AAD::지형_코어` | 코어 DEM 메시 + 고해상도 항공사진 텍스처 |
| `AAD::대상필지` | 검색한 대지 경계 (주황) — 지형 위에 얹힘 |
| `AAD::인접필지` | 대상지에 인접한 필지만 (회색) |
| `AAD::주변건물` | **브이월드 3D 건물 실물** (단색 또는 텍스처). 데이터가 없는 지역만 건축물대장 높이 압출로 대체 |
| `AAD::대지정보` | 용도지역·면적·도로접면·가져온 규모 요약 |

항공사진은 **지형 메시의 텍스처**로 들어간다. 평면(PictureFrame)으로 깔면
지형에 가려 보이지 않기 때문이다. 텍스처는 Rendered/Raytraced 표시 모드에서 보인다.

텍스처는 **JPEG(품질 85), 최대 4096px** 로 저장한다. PNG 로 두면 같은 그림이 5~10배
커지고 디코딩도 느려서, 라이노가 파일을 열 때 "응답 없음" 상태가 된다
(실측: 13.4MB PNG → 1.45MB JPEG, 3dm 26.4MB → 9.6MB).

필지선은 **대상지와 인접 필지만** 만든다. 광역 전체 필지선은 도면을 어지럽히기만 한다.
도로·하천처럼 수 km로 이어진 필지는 제외한다(반경 300m 요청에 2,441m 도로가
딸려오던 문제).

건물·필지선은 모두 **지형 고도 위**에 놓인다. Z=0에 두면 지형에 묻힌다.

건물 타일 수는 **먼저 `probe=1` 로 세고 그만큼 요청한다**. 고정값(40장)으로 두었더니
반경 500m 에 필요한 239장 중 40장만 받아 건물이 1/3 만 들어왔다.

**LOD 는 최하위까지 내려간다**(`detail=0`). 중간 LOD(`detail=5`)에서 멈추면 타일은
106장으로 줄지만 큰 건물만 들어오고 저층 건물이 통째로 빠진다.

| detail | 타일 | 건물 | 정점 | 시간 |
|---|---|---|---|---|
| 5 (중간 LOD) | 106장 | 105동 | 195,538 | 7초 |
| **0 (최하위)** | 239장 | **393동** | 165,526 | 14초 |

최하위 쪽이 건물은 3.7배 많은데 정점은 오히려 적다 — 중간 LOD 타일이 넓은 영역을
통짜 메시로 담고 있기 때문이다. 타일이 상한(600장)에 걸리면 대지정보에 경고를 남긴다.

## 실측 (압구정로29길 17, 광역 5km + 코어 500m)

```
전체 4초
지형_광역  정점 65,424 · 10,000×10,000m · Z -15.2~270.1m
지형_코어  정점 50,625 · 1,000×1,000m · Z 2.8~25.8m
주변건물   38동 (브이월드 3D 실물) · Z 11.9~71.0m
대상필지 1 · 인접필지 10 · 총 객체 64
```

건물 재질에 따른 차이 (같은 형상·같은 객체 수):

| | 3dm | 문서 재질 | 텍스처 |
|---|---|---|---|
| 단색 매스 | **7.79MB** | **3개** (지형2 + 건물1) | 지형 2장 |
| 실사 텍스처 | 9.65MB | 40개 | 지형 2 + 건물 38장 |

대상 필지 면적은 574.4㎡로 지적공부 573.4㎡와 0.17% 차이 — 좌표 변환이 실무에 쓸 만한 수준이다.

**필지는 부담이 아니다** (반경 500m에 539개·정점 5,328개·0.34MB).
병목은 항공사진이다 — 500m를 z20으로 깔면 타일 1,156장·8,704px(원본 289MB)가 된다.
그래서 반경이 커지면 줌을 낮춘 조합만 제공한다.

## 데이터 출처

- 지형(DEM): 브이월드 XDServer `Layer=dem` — 타일당 65×65 float32, 최대 레벨 15(약 1.5m)
  REST 키가 아니라 3D 전용 토큰이 필요해 서버가 `selectApiKeyJson.do`로 발급받는다.
  **DEM은 저장·캐싱하지 않는다** (국토부 보안규정, CLAUDE.md 절대 규칙)
- 항공사진: 브이월드 WMTS Satellite
- 필지: 연속지적도 `LP_PA_CBND_BUBUN`
- **3D 건물: 브이월드 3D Tiles(b3dm)** — 서울 자치구별 타일셋. Draco 압축·텍스처 포함.
  서버가 타일을 받아 RTC_CENTER(ECEF) 기준 좌표를 대지 중심 로컬 미터로 옮기고
  하나의 `.3dm`(버전 6) + 텍스처 PNG 로 만들어 준다.
- 건물 대체 경로: 건축물대장 `getBuildingUse` — 3D 데이터가 없는 지역에서만 쓴다
  (높이가 0으로 기재된 경우 층당 3.3m로 추정)

### 왜 .3dm 으로 주는가

Rhino 7 은 glTF 를 **내보내기만** 하고 가져오지 못한다(가져오기는 Rhino 8부터).
OBJ 는 가져올 수 있지만 스크립트로 억제할 수 없는 모달 대화상자를 띄워 자동화가 막힌다.
그래서 서버가 `rhino3dm` 으로 네이티브 3dm 을 만들고, 스크립트는 `_-Import` 대신
RhinoCommon 의 `File3dm.Read` 로 직접 읽어 문서에 넣는다 — 대화상자가 뜨지 않는다.
3dm 은 버전 6으로 저장한다(기본값은 최신 포맷이라 Rhino 7 이 열지 못한다).
`format=obj` / `format=glb` 로 다른 형식도 받을 수 있다.

## 아직 없는 것

- 정식 배포 형태(.rhp 플러그인, Yak 패키지) — 지금은 `AAD` 별칭 + 스크립트 파일이다.
  다른 PC 에 설치하려면 프로젝트 폴더를 복사하고 `install_aad.py` 를 한 번 실행해야 한다
- 툴바 버튼 (지금은 명령어 입력만)
- 반대 방향(라이노 매스 → AAD 앱으로 전송해 검토·렌더)
- **레이어 이름·색 최종 정리** — 사용자 검토 예정
